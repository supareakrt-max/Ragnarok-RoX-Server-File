# AI Bot (NPC ผู้เล่นจำลอง) สำหรับ rAthena

ระบบนี้ทำให้มี "ผู้เล่นจำลอง" ออนไลน์ในเกม เดินฟาร์มมอน ขายของ เข้าปาร์ตี้ และคุยแชทได้
แบ่งเป็น 2 ส่วน:

1. **Bridge ในเซิร์ฟเวอร์ (C++)**: `src/map/aibot.cpp` เปิดพอร์ต TCP ให้สมองกลภายนอกส่งคำสั่งได้
   ตัวละครบอทเป็นตัวละครจริงในตาราง `char` ที่ล็อกอินโดยไม่ต้องมีเกมไคลเอนต์ (ใช้กลไกเดียวกับ `@autotrade`)
   จึงเดิน ตี ใช้สกิล เก็บของ เข้าปาร์ตี้ และแชทได้เหมือนผู้เล่นจริงทุกอย่าง
2. **สมองกล (Python)**: `tools/aibot/` ตัดสินใจว่าบอทแต่ละตัวจะทำอะไร ใช้แค่ไลบรารีมาตรฐานของ Python 3.9+ ไม่ต้องติดตั้งอะไรเพิ่ม

รายละเอียดโปรโตคอลอยู่ที่ [`doc/aibot_protocol.md`](../../doc/aibot_protocol.md)

---

## ติดตั้ง

### 1. คอมไพล์เซิร์ฟเวอร์ใหม่
- **Windows (Visual Studio):** เปิด `rAthena.sln` แล้ว Build ได้เลย (เพิ่ม `aibot.cpp` เข้าโปรเจกต์ไว้แล้ว)
- **Linux:** `./configure && make server` หรือใช้ CMake

ตอนเปิด map-server จะเห็นบรรทัด
```
[Status]: AI bot bridge listening on '127.0.0.1:7100'
```

### 2. ตั้งค่า `conf/aibot.conf`
ค่าเริ่มต้นใช้งานได้เลย ถ้าต้องการแก้ ให้แก้ที่ `conf/import/aibot_conf.txt`
- `token:` ควรตั้งเสมอ ถ้าสมองกลไม่ได้รันบนเครื่องเดียวกับเซิร์ฟเวอร์
- `client_encoding: cp874` สำหรับไคลเอนต์ภาษาไทย (แปลงแชทไทยให้อัตโนมัติ)
- `max_bots`, `state_interval` ใช้จูนภาระของเซิร์ฟเวอร์

### 3. สร้างบัญชีและตัวละครบอท
```bash
cd tools/aibot
python create_bots.py --count 20 --min-level 1 --max-level 30 --out bots.sql --config-out bots.json
mysql -u <user> -p <database> < bots.sql
```
บอทใช้ account_id ตั้งแต่ 3000000 ขึ้นไป จึงไม่ชนกับผู้เล่นจริง แต่ละตัวได้อาชีพชั้น 1 แบบสุ่ม อาวุธเริ่มต้น และยาแดง
(ถ้าอยากใช้ตัวละครที่มีอยู่แล้ว ก็ใส่ชื่อตัวละครนั้นใน config ได้เลย)

### 4. ตั้งค่าสมองกลและรัน
```bash
cp config.example.json config.json
# เอารายชื่อบอทจาก bots.json มาใส่ในหัวข้อ "bots" ของ config.json
python run_brain.py -c config.json
```

## เปิดใช้ AI คุย (Gemini ฟรี)

1. **สมัคร key ฟรี (ไม่ต้องใช้บัตรเครดิต)**
   - Gemini: https://aistudio.google.com → Get API key
   - Groq (ตัวสำรอง ไม่มีก็ได้): https://console.groq.com → API Keys
2. **ตั้ง key เป็นตัวแปรสภาพแวดล้อม** อย่าใส่ key ลงไฟล์ config
   ```bat
   :: Windows (ตั้งถาวร แล้วเปิดหน้าต่าง cmd ใหม่)
   setx GEMINI_API_KEY "ใส่key"
   setx GROQ_API_KEY "ใส่key"
   ```
   ```bash
   # Linux
   export GEMINI_API_KEY="ใส่key"
   ```
3. **เปิดใน `config.json`:** `"llm": {"enabled": true, ...}`
4. **ทดสอบ key:** `python test_llm.py -c config.json` ถ้าได้ `[gemini] OK ...` พร้อมคำตอบภาษาไทย แปลว่าใช้ได้

**การทำงาน**
- ใช้ตัวแรกในรายการ `providers` ก่อน ถ้าโดนจำกัดความถี่ (429) โควต้าวันนั้นเต็ม หรือเชื่อมต่อไม่ได้ จะสลับไปตัวถัดไปเอง
- ถ้าหมดทุกตัว บอทกลับไปใช้ประโยคสำเร็จรูป เกมไม่พัง และ**ไม่มีค่าใช้จ่าย**
- `daily_limit` ตั้งให้ต่ำกว่าโควต้าฟรีจริงเล็กน้อยเพื่อความปลอดภัย จำนวนที่ใช้ไปถูกบันทึกใน `llm_usage.json` รีสตาร์ทก็ไม่นับใหม่
- `rpm` จำกัดจำนวนครั้งต่อนาทีไม่ให้เกินโควต้าฟรี
- `only_bots`: ใส่ชื่อบอทที่ให้ใช้ AI จริง เช่น `["NongFern", "PBank"]` ตัวอื่นใช้ประโยคสำเร็จรูป ช่วยประหยัดโควต้า (ว่าง = ทุกตัว)
- ถ้า Google เลิกให้ใช้ `gemini-2.5-flash` ฟรี ให้เปลี่ยน `"model"` เป็นรุ่นใหม่ที่เห็นใน AI Studio เช่น `gemini-3.5-flash`
- รายงานทุก 60 วินาทีมีบรรทัด `[report] LLM ...` บอกว่าใช้ไปเท่าไหร่แล้ว

> หมายเหตุ: ข้อมูลที่ส่งผ่าน API ฟรีของ Google อาจถูกนำไปใช้ปรับปรุงโมเดล ควรอ่านเงื่อนไขของ Google ก่อนใช้งาน

## Checklist เทียบกับแผนงาน

### Phase 1: โครงสร้างพื้นฐานในเกม
| งาน | ทำที่ |
|---|---|
| ตัวละครจำลอง | ตัวละครจริงที่ไม่มีไคลเอนต์ (`state.aibot`) ล็อกอินด้วยคำสั่ง `login` |
| API / Protocol | TCP + JSON ทีละบรรทัด มี 30 คำสั่ง (เดิน ตี สกิล ไอเท็ม ปาร์ตี้ แชท ...) และ server ส่งสถานะบอทออกมาทุก 500ms |
| ดักจับแชท | แชทสาธารณะใกล้บอท, ซิบหาบอท, แชทปาร์ตี้ และคำเชิญปาร์ตี้ ถูกส่งต่อไปที่สมองกลเป็น event |

### Phase 2: สมองกลภายนอก
| งาน | ไฟล์ |
|---|---|
| กิจวัตรประจำวัน | `aibot/routine.py`: ตารางเวลาต่อนิสัย (ฟาร์ม / เข้าเมือง / พัก / สังสรรค์) แต่ละตัวเลื่อนเวลาแบบสุ่ม และปรับ `time_scale` ให้เวลาเดินเร็วเพื่อทดสอบได้ |
| ต่อสู้ | `aibot/agent.py` `do_farm` / `survival`: เลือกเป้าหมายตามเลเวล ไม่แย่งมอนคนอื่น, ใช้สกิลตามอาชีพ, กินยา, หนีหรือวาร์ปกลับเมืองเมื่อเลือดน้อย, หนีบอส MVP |
| นิสัย | `aibot/personality.py`: `hardcore`, `merchant`, `chill` (เพิ่มเองได้ใน config) แต่ละแบบมีความก้าวร้าว ความถี่แชท คำพูด และตารางเวลาต่างกัน |
| LLM | `aibot/llm.py`: ใช้ **Gemini ฟรี** เป็นหลัก สำรองด้วย **Groq ฟรี** (รองรับ Claude และ Ollama ด้วย) ดูหัวข้อ "เปิดใช้ AI คุย" ด้านล่าง |

### Phase 3: เศรษฐกิจและสังคม
| งาน | ทำอย่างไร |
|---|---|
| กระเป๋า/ไอเท็ม | เก็บของดรอป → น้ำหนักเกิน `sell_weight` → เข้าเมือง ขายของ ซื้อยา เปลี่ยนชุดที่ดีกว่าและใส่ได้ตามเลเวล |
| ปาร์ตี้ | รับคำเชิญตามนิสัย (`accept_party`), ชวนผู้เล่นจริงที่เลเวลใกล้กันเข้าปาร์ตี้ (`invite_party`), คุยในแชทปาร์ตี้ |
| สุ่มเหตุการณ์ | บ่นตีบวกแตก, บ่นแลค, ดีใจตอนการ์ดหรือของแรร์ตก (ตรวจจากของเข้ากระเป๋าจริง), ตะโกนหนี MVP, อีโมท |

### Phase 4: ทดสอบและจูน
| งาน | เครื่องมือ |
|---|---|
| Load test | `python loadtest.py --count 200 --pid <pid ของ map-server>` แสดง latency p50/p95/p99, CPU, RAM |
| Pathfinding / Un-stuck | บอทที่ตั้งใจเดินแต่อยู่ที่เดิม 3 tick จะก้าวหลบไปช่องที่เดินได้ (อ่านจาก `db/map_cache.dat`) ถ้ายังติดจะวาร์ป จุดที่ติดบันทึกใน `stuck_report.csv` พร้อมจำนวนช่องว่างรอบตัว (ช่องน้อย = มุมตึก) |
| ความถี่คำสั่ง | `tick` / `tick_jitter` ต่อนิสัย, `max_commands_per_sec` (จำกัดรวมทุกบอท), `state_interval` และ `max_commands_per_cycle` ฝั่งเซิร์ฟเวอร์ |

### ผลทดสอบจริง (Linux, 4 cores, MariaDB, ไม่มีผู้เล่นจริงดูอยู่)
| จำนวนบอท | CPU map-server เฉลี่ย / สูงสุด | RAM เพิ่มขึ้น | latency p95 | timeout |
|---|---|---|---|---|
| 100 | 1.7% / 3.5% | +15 MB | 0.60 ms | 0 |
| 500 | 4.8% / 6.0% | +105 MB | 0.64 ms | 0 |

ถ้ามีผู้เล่นจริงยืนมองบอทจำนวนมาก เซิร์ฟเวอร์ต้องส่งแพ็กเก็ตหาไคลเอนต์มากขึ้นตาม ควรลองทดสอบกับเครื่องจริงของคุณด้วย

## ข้อจำกัดที่รู้อยู่
- การซื้อขายใช้ราคา item_db โดยตรง บอทจะเดินไปจุด `shop` ในเมืองให้ดูสมจริง แต่ไม่ได้คุยกับ NPC ร้านค้าจริง
- การเดินทางข้ามแมพใช้คำสั่ง `warp` (เหมือนใช้ Kafra หรือ Butterfly Wing) ไม่ได้เดินผ่านประตูวาร์ป
- ยังไม่เปลี่ยนอาชีพให้อัตโนมัติ (บอทอยู่ในอาชีพที่สร้างมา)
- รองรับ map-server ตัวเดียว (ถ้ามีหลาย map-server บอทจะวาร์ปข้ามเซิร์ฟเวอร์ไม่ได้)
- บอทเป็นตัวละครจริง จึงนับเป็นคนออนไลน์ และโผล่ใน `@who` / รายชื่อออนไลน์

## โหมดวนรอบ (farm ยาว → กลับเมืองซื้อของ + พัก → ออกใหม่)

ใส่ใน `config.json` แล้วรีสตาร์ทสมองกล บอทจะไม่ใช้ตารางเวลาจริงอีก

```json
"cycle": {"enabled": true, "farm_minutes": [60, 120], "town_minutes": [5, 10]},
```

- `farm_minutes`: ออกเก็บเวลนานเท่าไร (สุ่มระหว่าง 2 ค่า, นาที)
- `town_minutes`: อยู่ในเมืองนานเท่าไร: ขายของ ซื้อยา/อุปกรณ์ แล้วนั่งพักจนครบเวลา
- รอบแรกสุ่มสั้นกว่าปกติ บอทจะได้ไม่กลับเมืองพร้อมกันทั้งเซิร์ฟ
- กระเป๋าเต็มก่อนครบเวลา บอทก็ยังกลับไปขายของตามเดิม
- ใช้เฉพาะบางนิสัยได้ เช่น `"personalities": {"hardcore": {"cycle": {"farm_minutes": [120, 180]}}}` หรือปิดรายนิสัยด้วย `{"cycle": {"enabled": false}}`
